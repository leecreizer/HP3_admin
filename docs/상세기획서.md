# HomePlanner3 Admin — 페이지별 상세 기획서

> 본 문서는 현재 동작하는 어드민 프로토타입을 기준으로 **각 페이지가 어떻게 동작하는지**(진입 → 화면 → 사용자 행동 → 상태 변화 → 규칙 → 예외)를 정의한 기획서입니다.
> 작성 기준일: 2026-06-17 · 데이터는 mock(localStorage), 실제 연동 시 API로 대체.

---

## 0. 문서 보는 법
- 각 페이지는 **진입 경로 / 화면 구성 / 동작 흐름 / 상태·규칙 / 예외**로 기술합니다.
- "동작 흐름"의 번호는 사용자가 실제로 수행하는 순서입니다.
- ⚠️ = 현재 mock이거나 미구현(실연동 필요).

## 1. 공통 동작 (전 페이지)

### 1.1 레이아웃·네비게이션
- 화면은 **좌측 사이드바 + 상단바 + 메인 콘텐츠** 3분할, 높이 100vh 고정.
- 사이드바·상단바는 **항상 고정**, 메인만 스크롤. 리스트형 페이지(상품·사용자)는 **툴바·표 헤더가 sticky**로 붙고 행만 스크롤.
- 좌측 메뉴 클릭 → 해당 페이지로 전환(SPA, 새로고침 없음). 홈 로고 = 대시보드.
- 메뉴 접기/펼치기: 아이콘만 보이는 축소 모드 ↔ 라벨 포함 확장 모드.

### 1.2 등급(권한)에 따른 메뉴 노출  ★핵심
- 운영자는 **등급**을 가지며, 등급별로 **접근 가능한 좌측 메뉴가 다름**.
- 현재 등급은 상단바 **사용자 이름 옆 배지**로 표시.
- 접근 불가 메뉴는 사이드바에 **노출되지 않음**. 권한 없는 페이지로 진입 시 "접근 권한 없음" 안내 후 첫 허용 메뉴로 이동.
- 등급 정의·메뉴 노출은 **사용자 관리 › 등급·노출 관리**에서 설정(§5).

### 1.3 데이터 영속화 (프로토타입)
- 설정/등급: `localStorage['hp3-admin-config']`
- 상품/폴더/분류/필터/노출필드 + UI상태: `localStorage['hp3-products-state']`
- ⚠️ 실제 서비스는 전부 서버 API + DB로 대체. localStorage는 데모용.

### 1.4 공통 인터랙션 패턴
- **검색**: 입력 즉시 필터(디바운스 없음, 클라이언트 필터).
- **상태/구분 탭**: 단일 선택, 클릭 시 목록 재필터.
- **정렬**: 표 컬럼 헤더 클릭 → 오름/내림 토글, 빈 값은 항상 뒤로.
- **페이지네이션**: 페이지당 20/50/100 선택, 1·2·3… 이동. 검색·필터·정렬 변경 시 1페이지로 리셋.
- **토글 스위치**: 즉시 반영(노출여부 등).
- **모달**: 배경 클릭 또는 취소로 닫힘, 저장 시에만 반영.
- **인라인 편집**: 입력 후 blur/Enter 시 저장.

## 2. 대시보드 (`/dashboard`)

### 진입 경로
- 홈 로고 클릭 / 기본 진입 페이지. 모든 등급 접근 가능.

### 화면 구성
- 페이지 헤더(타이틀 + 오늘 날짜 + `리포트 내보내기`)
- KPI 카드 4종 / 렌더 처리 추이 차트 / 렌더 큐 / 최근 완료 렌더 표.

### 동작 흐름
1. 진입 시 오늘 기준 KPI(오늘 렌더·DAU·평균 렌더시간·실패율)와 전일·전주 대비 증감을 표시.
2. 렌더 처리 추이: 최근 14일 완료/실패 추이 라인. `최근 14일 ›`로 기간 확장(⚠️).
3. 렌더 큐: 처리중/대기/완료/실패 상태를 실시간 표시(⚠️ 폴링/WS 필요).
4. 최근 완료 렌더 표: 컬럼 정렬 가능, `렌더 작업으로 이동`(⚠️).
5. `리포트 내보내기`: 현재 지표를 파일로 내보냄(⚠️).

### 상태·규칙
- 실패율 = 실패/(완료+실패) 당일 누계, 평균시간은 성공 건만 집계.

## 3. 도면 관리 (`/floorplans`)

### 진입 경로
- 좌측 `도면 관리`. (접근 권한 있는 등급만)

### 화면 구성 / 동작 흐름 — 목록
1. 툴바: 검색(단지명·평형·도면ID), 상태 탭(전체/공개/검수중/임시저장), 정렬(최신수정/이름/평형).
2. 도면 카드 그리드: 썸네일·단지·평형·구성·도면ID·렌더 수.
3. 카드 클릭 → **상세 뷰** 진입.
4. `도면 등록`(⚠️ 미구현) → 업로드 모달 예정.

### 동작 흐름 — 상세
1. 헤더: `‹ 도면 목록` 복귀, 도면명, 상태 배지, `렌더 생성`(⚠️).
2. 좌측: 도면 메타(ID/단지/평형/수정일/렌더수).
3. 우측: **렌더 이미지 갤러리** — 공간(거실/주방/침실…) 탭 필터(해당 도면 렌더의 room으로 자동 구성).
4. 렌더 카드: 스타일·생성일·소요시간, 휴지통으로 삭제.

### 상태·규칙
- 렌더 이미지는 **반드시 해당 도면에 종속**. 다른 도면의 렌더는 보이지 않음.
- 상태값: 공개/검수중/임시저장 3종.

## 4. 사용자 관리 (`/users`)

### 진입 경로
- 좌측 `사용자 관리`. 하위에 `등급·노출 관리`(§5)가 펼쳐짐.

### 화면 구성
- 헤더(전체 인원·그룹 수 + `사용자 추가`) / 요약 KPI(전체·활성·휴면·차단)
- 좌측 **그룹 트리 패널**(브랜드 > 그룹), 우측 **사용자 표 패널**.

### 동작 흐름
1. 그룹 트리에서 범위 선택: `전체 사용자` / `브랜드`(그 브랜드 전체 그룹원) / `개별 그룹` → 우측 목록이 해당 범위로 필터.
2. 검색(이름·이메일·ID) + 상태 탭(전체/활성/휴면/차단) + 컬럼 정렬 + 페이지네이션.
3. **사용자 추가**(`+ 사용자 추가`): 모달에서 입력 → 저장.
   - 필수: **이름·사번·조직**(미입력 시 저장 버튼 비활성). 선택: 이메일·종료일·등급·상태·소속 그룹(복수).
4. **사용자 수정**: 행의 ✏️ → 동일 모달.
5. **사용자 삭제**: 행의 🗑️ 또는 체크 후 일괄 삭제.
6. **선택 → 그룹 추가**: 체크한 사용자들을 특정 그룹에 일괄 편입.
7. **그룹 관리(트리에서 직접)**: 브랜드에 호버 → `＋`로 그룹 추가 / 그룹 더블클릭·✏️ 이름변경 / 🗑️ 삭제 / 드래그로 순서·소속 이동.

### 상태·규칙
- 사용자–그룹은 **N:M**. 사용자의 "브랜드"는 소속 그룹에서 자동 도출(직접 보유 안 함).
- 그룹/브랜드 변경은 **브랜드 관리(§6)와 동일 데이터로 연동**.
- 그룹 삭제 시 사용자는 유지되고 **소속만 해제**.
- 등급(일반/B2B/VIP 등)은 등급·노출 관리의 서비스 등급 목록에서 선택지로 제공.

### 예외
- 무소속 사용자: 브랜드/그룹 칸은 `–`, 정렬 시 뒤로.

## 5. 등급 · 노출 관리 (`/users/roles`)  ★권한 시스템

### 진입 경로
- `사용자 관리` 하위 메뉴 `등급·노출 관리`.

### 화면 구성
- **운영자 등급 · 메뉴 노출** 표 1종(등급 행 × 메뉴 열의 체크박스 매트릭스).

### 동작 흐름
1. 등급 행마다 **등급명 인라인 편집**(테두리 입력 필드, 즉시 저장).
2. 각 메뉴 열의 체크박스로 **해당 등급의 메뉴 접근 허용/차단** 지정.
3. `+ 운영자 등급 추가` → 새 등급 행 생성(기본 대시보드만 허용).
4. 기본이 아닌 등급은 🗑️로 삭제.

### 상태·규칙
- **홈 대시보드는 항상 접근**(체크 고정·비활성).
- **최고관리자는 전체 메뉴 고정**(수정 불가).
- 기본 등급(최고관리자/운영자/뷰어)은 삭제 불가, 이름은 변경 가능.
- 변경 즉시 좌측 사이드바 노출에 반영(상단바 등급 배지 기준).
- 메뉴 열: 홈 대시보드·사용자 관리·브랜드 관리·도면 관리·상품 관리·통계 분석·설정.

### 비고
- 서비스 사용자 등급(일반/B2B/VIP)은 데이터로 유지되어 사용자 모달의 등급 선택지로 사용(이 화면에는 미표시).

## 6. 브랜드 관리 (`/brands`)

### 화면 구성 / 동작 흐름
1. 브랜드(파트너사) 목록 표: 브랜드명(인라인 편집) / 소속 그룹(태그) / 삭제.
2. `브랜드 추가`: 하단 입력 → 추가(이름 중복 불가).
3. 그룹 추가: 브랜드 행의 `+`로 하위 그룹 생성, 태그의 `×`로 그룹 삭제.
4. 브랜드 삭제: 하위 그룹이 있으면 **확인 후 그룹까지 함께 삭제**(사용자 소속 자동 해제).

### 상태·규칙
- 브랜드/그룹은 **사용자 관리·상품 컨텐츠 권한과 동일 데이터로 연동**.

## 7. 상품 관리 (`/products`)  ★최다 기능

### 7.1 메인: 상품 리스트
#### 화면 구성
- 좌측 **폴더 트리 패널**(너비 드래그 조절), 우측 **상품 표 패널**(툴바·헤더 sticky).
- 표 컬럼: 체크 / 상품명(썸네일·권한태그) / 브랜드 / 상품군 / 모델 / 품목구분 / 견적그룹 / 컨텐츠코드 / 상품코드 / 노출여부 / 배치위치 / 사이즈 / 속성구분 / 수정일자 / 관리.

#### 동작 흐름
1. 폴더 선택 → 해당 폴더(및 하위) 상품만 표시.
2. 검색(상품명·컨텐츠코드·상품코드) + 속성구분 탭(전체/배치형·설계형 모델링/텍스쳐/머터리얼) + 정렬 + 페이지네이션.
3. 노출여부 토글 즉시 반영.
4. 체크 후 `폴더로 이동` / `삭제` 일괄 처리.
5. `상품 등록`(모달) / 행 ✏️로 **편집 화면** 진입.

#### 폴더 트리 동작
- **미분류 루트 고정**(삭제·이동·이름변경 불가), 모든 폴더는 그 아래.
- `+ 새 폴더`: 현재 선택 폴더 하위에 생성(미선택 시 미분류).
- 펼침/접힘(캐럿), 이름변경(✏️·더블클릭·F2), 삭제(🗑️ — 내부 상품은 상위로, 하위폴더 있으면 삭제 불가).
- **이동은 드래그&드롭만**(위쪽 1/3=같은 레벨 앞, 나머지=하위로).

### 7.2 상품 등록 / 편집
- **편집 화면 = 3패널**: 썸네일·에셋 / 기본정보 / 컨텐츠 운영정보. `나가기`(미저장 원복) + `저장`.
- **기본정보 순서**: 상품명 · 브랜드 · 견적그룹 · 상품군 · 상품구분(상품군 선택 시 해당 군의 품목) · 컨텐츠코드 · 상품코드 · 컨텐츠권한(사용자 그룹) · 노출여부 · 속성구분 · 컨텐츠크기 · 배치위치·배치높이 · 스펙URL · mallURL · 필터(추가식).
- **썸네일**: 400×400 업로드(없으면 기본 이미지). **에셋**: 확장자 자동 인식 + three.js 미리보기. ⚠️ AssetBundle은 서버 glTF 변환 필요.
- **컨텐츠 운영정보**: 상품군+상품구분 조합별 항목(⚠️ 매핑 정의 예정).
- 등록 모달도 동일 기본정보 구성.

### 7.3 하위 메뉴
- **상품군·구분 관리**: 상품군 + 품목(구분) 추가/이름변경/삭제, 상품 동기화.
- **모델 관리**: 상품군별 모델(시리즈) 관리.
- **노출 필드 관리**: 등록 시 노출되는 DB 필드 정의(현재값=기본세팅) + 저장. 시스템 기본필드 삭제 불가.
- **필터 관리**: 필터 그룹+옵션 2단. '상품 구분·모델 구분' 필터는 읽기전용(각 메뉴 데이터 연동).

### 상태·규칙
- `productCode`(가격코드) 수정 불가, `contentCode` PK.
- 속성구분=텍스쳐/머터리얼이면 사이즈 0·모델링구분 없음.
- 모든 변경은 localStorage에 즉시 저장(새로고침·재방문 유지).

## 8. 설정 (`/settings`)

### 화면 구성 / 동작 흐름
1. **좌측 메뉴 관리**: 순서(▲▼)·이름(인라인)·표시 토글·추가·삭제.
2. **상품관리 하위메뉴 관리**: 순서·이름·표시(키 고정).
3. **상부 메뉴 관리**: 브랜드명/부제·검색창 표시·placeholder·관리자 이름/역할/계정.
4. `기본값으로 되돌리기`로 전체 초기화.

### 상태·규칙
- 삭제한 기본 메뉴는 부활 방지(`removedMenus`). 변경 즉시 사이드바/상단바 반영·저장.
- ⚠️ 실제로는 조직/관리자 단위 서버 저장 + 등급별 기본값 필요.

## 9. 페이지 간 데이터 연동 관계

```
브랜드/그룹(org)  ── 사용자 관리(소속) · 브랜드 관리(편집) · 상품 컨텐츠 권한(선택)  ⟷  동일 데이터
등급(roles)       ── 등급·노출 관리(정의) → 사이드바 메뉴 노출 · 상단바 등급 배지 · 사용자 등급 선택지
상품군/품목/모델   ── 상품 기본정보 선택지 · 필터(상품/모델 구분) 파생
폴더              ── 상품 분류/이동
도면              ── 1:N 렌더 이미지
```

---

## 10. 상태·예외 동작 요약
- **권한 없음**: 등급에 없는 메뉴 → 사이드바 미노출, 직접 진입 시 안내 + 자동 이동.
- **빈 목록**: "조건에 맞는 ○○이 없습니다" 안내 행.
- **미저장 이탈**: 상품 편집에서 `나가기` 시 변경(에셋·썸네일 포함) 전부 원복.
- **새로고침**: localStorage 기반으로 데이터·UI 상태(선택 폴더·접힘·패널 너비) 유지. 단, 업로드 blob 미리보기는 소실(파일명·종류만 유지).

## 11. 정책 (Policy)

### 11.1 권한·접근 정책
- **어드민 접근**: 운영자 등급만 어드민 로그인 가능. 일반/B2B 등 서비스 사용자는 어드민 접근 불가.
- **메뉴 접근**: 등급별 메뉴 노출 매트릭스(등급·노출 관리)를 단일 기준(Single Source)으로 함. 코드/화면에서 별도 하드코딩 금지.
- **최소 권한 원칙**: 신규 등급의 기본값은 홈 대시보드만 허용. 필요한 메뉴만 추가 부여.
- **고정 권한**: 최고관리자=전체 고정, 홈 대시보드=전 등급 항상 허용. 시스템 기본 등급(최고관리자/운영자/뷰어)은 삭제 불가.
- **권한 변경 즉시 반영**: 등급 권한 수정 시 사이드바 노출·페이지 접근에 즉시 적용. 권한 없는 페이지 직접 진입은 차단 후 안내.

### 11.2 데이터 정책
- **단일 출처(SSOT)**: 브랜드/그룹은 사용자·브랜드·상품권한이 공유. 상품군/품목/모델은 상품 기본정보·필터가 공유. 중복 정의 금지.
- **식별자**: 상품 `contentCode`=PK(배치 키), `productCode`=가격코드(수정 불가). 사용자=`사번`을 업무 식별 기준.
- **연쇄 정리(Cascade)**: 브랜드 삭제 시 하위 그룹 삭제 + 사용자 소속 해제. 그룹 삭제 시 사용자 유지·소속만 해제. 폴더 삭제 시 상품은 상위 폴더로 이동.
- **필수값**: 사용자=이름·사번·조직, 상품=상품군·상품명·코드·노출·권한 등 노출 필드 관리의 `필수` 정의를 따름.
- **불변/감사**: 모든 변경은 `수정일자·수정자` 기록(상품). 가격코드 등 기준정보성 값은 어드민에서 임의 변경 금지(기준정보 시스템 동기화).

### 11.3 노출·운영 정책
- **노출여부**: 설계페이지 상품 리스트 노출은 `노출여부` 토글로 제어. 미완성/검수중 컨텐츠는 비노출 원칙.
- **컨텐츠 권한**: 상품은 `전체` 또는 특정 그룹 한정 노출. 파트너사 전용 컨텐츠는 해당 그룹으로 제한.
- **도면-렌더 종속**: 렌더 이미지는 소속 도면을 벗어나 단독 존재하지 않음. 도면 상태(공개/검수중/임시저장)에 따라 노출 단계 관리.
- **명명 규칙**: 등급·그룹·폴더·상품군 명칭은 중복 불가 권장, 사용자 식별이 쉬운 한글 표기 우선.

### 11.4 보존·영속 정책
- 프로토타입은 localStorage 보존(브라우저/기기 한정). **실서비스는 서버 저장이 원칙**이며 localStorage는 캐시·UI 상태로 한정.
- 업로드 에셋/이미지는 서버 저장 + 영속 URL 필요. blob(임시 URL)은 보존 대상 아님.
- 기준 구조(시드/스키마) 변경 시 저장 버전을 올려 구버전 저장본을 무효화(데이터 정합성 보장).

### 11.5 보안·컴플라이언스 정책
- 개인정보(이메일·사번 등)는 마스킹 표기 원칙(목록 노출 시 부분 마스킹).
- 권한 변경·삭제 등 민감 동작은 감사 로그 대상(⚠️ 실연동 시 적용).
- 외부 공개(LAN/터널) 시 인증 없는 정적 문서만 허용, 운영 데이터 API는 인증 필수.
