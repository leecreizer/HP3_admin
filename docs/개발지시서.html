HomePlanner3 Admin — 상세 개발 지시서

본 문서는 현재 동작하는 프로토타입(c:\workspace\HP3_admin) 을 기준으로,
각 페이지의 기능을 도출하고 실제 백엔드/연동 개발을 진행하기 위한 지시서입니다.
개발자는 프로토타입을 띄워(npm run dev → http://localhost:5173) 화면을 보며 본 문서를 참조하세요.

0. 문서 사용법

  • 페이지별 섹션은 다음 형식으로 구성됩니다.
    • 화면 구성 — 무엇이 보이는가
    • 기능 도출 — 사용자가 할 수 있는 동작(번호 매김 = 개발 단위)
    • 데이터 모델 — 프론트 타입 → DB/DTO 매핑
    • API — 필요한 엔드포인트 초안
    • 비즈니스 규칙 — 반드시 지켜야 하는 제약
    • 인수 조건(AC) — 완료 판정 기준
  • 프로토타입의 현재 한계(mock·미구현)는 ⚠️ 로 표기합니다.

1. 공통 사양 (전 페이지 공통)

1.1 레이아웃 셸

  • 그리드 셸: 좌측 사이드바(266px, 접으면 104px) / 상단바(72px) / 메인(1fr). 전체 높이 100vh 고정.
  • 상단바·사이드바는 스크롤 시 고정, 메인 콘텐츠만 스크롤. 리스트형 페이지(상품/사용자)는 툴바·테이블 헤더도 sticky 고정되고 행만 내부 스크롤됩니다. (구현 참조: .product-panel { max-height: calc(100vh - 184px); overflow:auto }, 툴바/thead th position:sticky)
  • 반응형: 좁은 화면에서 products-layout이 1단으로 접힘.

1.2 사이드바(좌측 메뉴) — components/Sidebar.tsx

  • 상단: 브랜드 로고(홈 대시보드 버튼) + 브랜드명/부제(설정에서 변경).
  • 메인 메뉴: 드래그로 순서 변경 가능, 설정에서 표시/숨김·이름변경·추가·삭제.
  • 상품 관리는 하위 메뉴(상품군·구분 관리 / 모델 관리 / 노출 필드 관리 / 필터 관리)를 펼침.
  • 시스템 메뉴: 설정. (※ API 모니터링은 제거됨)
  • 하단: 메뉴 접기/펼치기 토글.
  • 요구: 실제 환경에서는 메뉴 노출이 로그인 사용자 권한(롤) 에 따라 필터링되어야 함(현재는 전부 노출).

1.3 상단바 — components/Topbar.tsx

  • 좌: 섹션/페이지 타이틀. 중: 검색창(설정으로 on/off·placeholder). 우: 알림 버튼(설정 on/off, 카운트), 로그인 사용자 정보(이름/역할/계정).

2. 대시보드 (/dashboard) — pages/Dashboard.tsx

화면 구성

  • 페이지 헤더(타이틀 + 오늘 날짜 + 리포트 내보내기)
  • KPI 4종: 오늘 AI 렌더 / 활성 사용자(DAU) / 평균 렌더 시간 / 렌더 실패율 (증감 델타 포함)
  • 렌더 처리 추이 차트(최근 14일, 완료/실패 라인) — RenderTrendChart
  • 렌더 큐(처리중/대기/완료/실패 상태 리스트)
  • 최근 완료된 렌더 테이블(작업/공간/사용자/처리시간/매칭상품/상태, 정렬 가능)

기능 도출

  1. KPI 카드 데이터 조회 (오늘 기준 집계 + 전일/전주 대비 증감)
  2. 렌더 추이 차트(기간 파라미터: 기본 14일, 최근 14일 › 링크 → 기간 선택)
  3. 렌더 큐 실시간 상태 표시(폴링 또는 WebSocket)
  4. 최근 완료 렌더 목록 + 컬럼 정렬 + 렌더 작업으로 이동
  5. 리포트 내보내기(CSV/엑셀 다운로드)

API

  • GET /api/dashboard/kpis?date=YYYY-MM-DD → { todayRenders, dau, avgRenderSec, failRate, deltas{} }
  • GET /api/dashboard/render-trend?days=14 → { done:number[], fail:number[], labels:string[] }
  • GET /api/renders/queue?status=&limit= → 큐 항목(아이콘/타이틀/요청자/상태)
  • GET /api/renders?status=done&sort=&limit= → 최근 렌더
  • GET /api/dashboard/report.csv?from=&to=

비즈니스 규칙

  • 실패율은 fail/(done+fail) 당일 누계. 평균 렌더 시간은 성공 건만.
  • 큐 상태값: run|wait|done|fail (디자인 토큰 st-*와 1:1).

인수 조건

  • [ ] KPI·차트·큐·최근목록이 실제 API 데이터로 렌더된다.
  • [ ] 큐는 최소 10초 주기로 갱신(또는 푸시).
  • [ ] 리포트 내보내기가 현재 필터 기준으로 파일을 생성한다.

4. 사용자 관리 (/users) — pages/Users.tsx

화면 구성

  • 헤더(전체 N명·그룹 M개 + 사용자 추가)
  • KPI 4종(전체/활성/휴면/차단)
  • 좌측 그룹 트리 패널(브랜드 > 그룹 계층, 너비 드래그 조절), 우측 사용자 테이블 패널
  • 테이블 컬럼: 체크 / 브랜드 / 사용자(아바타·이름·이메일) / 사번 / 조직 / 권한 / 그룹 / 가입일 / 종료일 / 렌더수 / 상태 / 관리(수정·삭제). 전 컬럼 정렬.
  • 추가/수정 모달.

기능 도출

  1. 사용자 목록 조회 + 검색(이름·이메일·ID) + 상태 필터(전체/활성/휴면/차단) + 전 컬럼 정렬 + 페이지네이션
  2. 그룹 트리로 범위 필터: 전체 사용자 / 브랜드 단위(그 브랜드의 모든 그룹원) / 개별 그룹
  3. 사용자 추가/수정 모달 — 필수: 이름·사번·조직 / 선택: 이메일·종료일·권한·상태·소속그룹(복수, 브랜드별 묶음 체크)
  4. 사용자 삭제(행 단위 / 선택 일괄)
  5. 선택 사용자 → 그룹에 일괄 추가
  6. 그룹 관리(트리에서 직접): 브랜드 호버 시 ＋로 그룹 추가, 그룹 더블클릭·✏️ 이름변경, 🗑️ 삭제(사용자는 유지·소속만 해제)
  7. 드래그: 브랜드 순서 변경, 그룹을 다른 그룹 앞/다른 브랜드 하위로 이동
  8. ※ 그룹·브랜드 변경은 브랜드 관리 메뉴와 동일 데이터로 연동(공유 상태). 브랜드 자체 추가·삭제는 브랜드 관리에서만.

데이터 모델

User { id, name, email?, empNo, org, role: 일반|B2B|운영자, joined, endDate?, lastSeen, renders:number, status: active|dormant|blocked, groupIds:string[] }
Group { id, name, brandId(FK) }   // org.ts 공유
Brand { id, name }                // org.ts 공유
// User ↔ Group : N:M (groupIds). 사용자의 "브랜드"는 소속 그룹의 brandId에서 도출(직접 보유 안 함).

API

  • GET /api/users?q=&status=&groupId=&brandId=&sort=&dir=&page=&size=
  • POST /api/users / PUT /api/users/{id} / DELETE /api/users/{id} / POST /api/users/bulk-delete
  • POST /api/groups/{id}/members (선택 사용자 일괄 추가)
  • 그룹: POST /api/groups PUT /api/groups/{id} DELETE /api/groups/{id} PATCH /api/groups/{id}/move
  • 브랜드 순서: PATCH /api/brands/reorder

비즈니스 규칙

  • 필수값: 이름·사번·조직(미입력 시 저장 불가). 이메일은 선택.
  • 그룹 삭제 → 해당 그룹을 모든 사용자 groupIds에서 제거(사용자 삭제 아님).
  • 사용자 브랜드 표기는 소속 그룹의 brandId 집합에서 계산.
  • 정렬: 빈 값(무소속/-)은 항상 뒤로('￿' 정렬 키 트릭과 동일 의미).

인수 조건

  • [ ] 필수 3종 미입력 시 추가/저장 버튼 비활성.
  • [ ] 그룹/브랜드 변경이 브랜드 관리 화면과 즉시 동기화된다.
  • [ ] 검색·필터·정렬·페이지네이션이 서버 기준으로 동작한다.

  • 좌측 폴더 트리 패널(너비 드래그 조절), 우측 상품 테이블 패널(툴바·헤더 sticky)
  • 툴바: 검색(상품명·컨텐츠코드·상품코드) + 속성구분 탭(전체/배치형 모델링/설계형 모델링/텍스쳐/머터리얼, 각 카운트) + 선택정보 + 폴더이동 select + 삭제
  • 테이블 컬럼: 체크 / 상품명(썸네일+권한태그) / 브랜드 / 상품군 / 모델 / 품목구분 / 견적그룹 / 컨텐츠코드 / 상품코드 / 노출여부(토글) / 배치위치(+높이) / 사이즈 / 속성구분 / 수정일자 / 관리(수정·삭제). 전 컬럼 정렬 + 페이지네이션.

기능 도출

  1. 상품 목록 조회 + 검색 + 속성구분 탭 필터 + 폴더(선택 폴더 및 하위 전체) 필터 + 정렬 + 페이지네이션
  2. 노출여부 토글(인라인)
  3. 상품 폴더 이동(선택 일괄 → 폴더로 이동)
  4. 상품 삭제(행/일괄)
  5. 폴더 트리:
    • 항상 미분류 최상위 루트 존재(삭제·이동·이름변경 불가)
    • + 새 폴더(선택 폴더 하위에 생성. 미선택 시 미분류 루트 하위)
    • 폴더 이름변경(✏️/더블클릭/F2), 삭제(🗑️ — 안의 상품은 상위 폴더로, 하위 폴더 있으면 삭제 불가)
    • 이동은 드래그&드롭만(상단 1/3 = 같은 레벨 앞, 나머지 = 하위로). 이동용 아이콘 없음.
    • 펼침/접힘(캐럿) + 직접 상품 수 카운트
  6. 상품 등록 모달(+ 상품 등록): 좌측 미디어(썸네일·에셋) + 우측 기본정보. 디테일 기본정보와 동일 필드.
  7. 상품 상세/편집 화면(행의 ✏️): 3-패널(썸네일·에셋 / 기본정보 / 컨텐츠 운영정보). 나가기(미저장 시 원복) + 저장.

  specUrls:{name,url}[], mallUrls:{name,url}[],

기본정보 필드 순서(등록/편집 공통)

상품명 · 브랜드 · 견적그룹 · 상품군 · 상품구분(상품군 선택 시 해당 군의 품목 리스트) · 컨텐츠코드 · 상품코드 · 컨텐츠권한(사용자 관리 그룹) · 노출여부 · 속성구분(배치형 모델링/설계형 모델링/텍스쳐/머터리얼 통합 선택) · 컨텐츠크기(직접입력, 기본=모델링 사이즈) · 배치위치 · 배치높이(배치위치 옆) · 스펙URL(+추가 시 이름·주소행) · mallURL · 필터(‘필터 추가’로 필터관리 생성목록에서 선택, 선택된 것만 표시)

컨텐츠 운영정보

  • 상품군 + 상품구분 조합별로 노출 항목이 달라짐(OPERATION_SPEC[${group}|${kind}]).
  • ⚠️ 현재 매핑 비어 있음 — 발주처(사용자)가 조합별 항목 정의 제공 예정. 구조만 구현됨.

에셋/썸네일

  • 썸네일 400×400 업로드(없으면 기본 이미지).
  • 에셋 업로드 시 확장자로 종류 자동 인식, three.js로 미리보기(glb/gltf/obj/fbx = 3D, 이미지 = img, 머터리얼 = 정보).
  • ⚠️ Unity AssetBundle은 브라우저 미리보기 불가 → 서버에서 glTF 변환 필요.
  • ⚠️ 업로드 blob은 새로고침 시 미리보기 소실(파일명·종류만 유지) → 실제로는 서버 저장 + URL 필요.

API

  • GET /api/products?q=&attrType=&folderId=&sort=&dir=&page=&size=
  • POST /api/products / PUT /api/products/{contentCode} / PATCH /api/products/{contentCode}/visible / DELETE / POST /api/products/bulk-(move|delete)
  • 폴더: GET/POST/PUT/DELETE /api/product-folders, PATCH /api/product-folders/{id}/move
  • 업로드: POST /api/products/{code}/thumbnail, POST /api/products/{code}/assets(다건), 에셋 변환 상태 폴링
  • 권한 셀렉터: 사용자 관리 그룹 재사용(GET /api/groups)

비즈니스 규칙

  • productCode(가격코드)는 수정 불가. contentCode는 PK.
  • 폴더 삭제 정책: 상품→상위 폴더, 하위폴더 있으면 차단, 최상위 미분류는 보호.
  • 속성구분=텍스쳐/머터리얼이면 사이즈 0·modelingType=null.
  • 필터의 상품 구분/모델 구분은 읽기전용(모델/상품구분 관리에서만 수정) — §6.5 참조.

인수 조건

  • [ ] 상품군 선택 → 상품구분 옵션이 해당 군으로 한정된다.
  • [ ] 나가기로 저장 전 변경(에셋·썸네일 포함)이 모두 원복된다.
  • [ ] 폴더 드래그 이동/이름변경/삭제 규칙이 서버에 반영된다.
  • [ ] 등록 모달과 편집 화면의 기본정보 필드가 동일하다.

6.2 하위: 상품군·구분 관리 (/products/catalog)

  • 상품군(부엌·바스·수납·도어·창호·가구·조명·소품·마감재 등) 추가/이름변경/삭제.
  • 각 상품군의 상품구분(품목) 칩 추가/이름변경/삭제.
  • 변경 시 관련 상품의 productGroup/productKind 동기화. 필터의 ‘상품 구분’ 파생목록과 연동.
  • API: GET/POST/PUT/DELETE /api/product-groups, .../kinds

6.3 하위: 모델 관리 (/products/models)

  • 상품군별 모델(시리즈: 노뜨/스위브/KB/EO/유로… 등) 폴더형 관리.
  • 필터의 ‘모델 구분’ 파생목록과 연동.
  • API: GET/POST/PUT/DELETE /api/product-models

6.4 하위: 노출 필드 관리 (/products/fields)

  • 컨텐츠 등록 시 노출되는 DB 필드 정의표(컬럼명/직접입력/필수/수정가능/예시).
  • 현재 기준값(브랜드·상품군·상품명·견적그룹·컨텐츠코드·상품코드·노출여부·권한·W/D/H·배치위치·배치높이·속성구분·상품구분·모델구분·필터·스펙url·mall url·AssetBundle·Binary·썸네일)을 기본 세팅으로.
  • 추가/수정/삭제 + 변경값 저장 버튼(saveFields) + 기본값 초기화. 시스템 기본필드(builtin)는 삭제 불가.
  • API: GET/PUT /api/product-fields

6.5 하위: 필터 관리 (/products/filters)

  • 필터 그룹(제목) + 옵션 2단 구조(예: 스타일=모던/내추럴/…, 색상=화이트/…, 공간=거실/…).
  • 그룹/옵션 추가·수정·삭제.
  • 기본 내장 필터 ‘상품 구분’·‘모델 구분’ 은 모델 관리·상품군 관리 데이터를 그대로 가져와 표시(읽기전용, 각 메뉴에서만 수정).
  • 상품 편집의 필터 picker에 노출.
  • API: GET/POST/PUT/DELETE /api/product-filters
