기업 상품 라이브러리는 설계 툴(쿠지알러 디자인 도구)에서 쓰는 모든 상품·소재의 원장입니다. 운영자는 여기서 소재를 올리고, 폴더로 분류하고, 상품 정보(모델번호·상품코드·브랜드·가격·태그)를 채우고, 설계 툴 노출 여부와 외부 공개·권한을 정합니다.

라이브러리(기업 / 추가 라이브러리) └ 업무 탭 10개 (모델·재질, 타일·바닥, 몰딩·벽판, 도료, 주방·욕실 맞춤 …) └ 소재 라이브러리 (모델 라이브러리, 재질 라이브러리, 조합 라이브러리 …) └ 폴더 트리 (최대 4~5단계: 가구 › 침실 › 침대 › …) └ 상품(소재) — 목록(표/카드) · 빠른 편집 · 상세 · 일괄 작업

2페이지별 작업 분석

각 화면에서 운영자가 실제로 하는 작업, 화면 구성, HP3에서 어떻게 옮겼는지를 차례로 적었습니다.

2-1 상품 목록 brandgoods/all

무엇을 하나
선택한 소재 라이브러리·폴더의 상품을 40개씩 보여 주고, 체크한 상품에 일괄 작업을 겁니다. 행 안에서 ‘도구 노출’ 스위치를 바로 켜고 끕니다.
화면 구성
① 라이브러리 탭(기업 라이브러리 = 주 라이브러리, 추가 라이브러리, + 새 라이브러리) ② 업무 탭 + 우측 ‘가져오기/내보내기 · 라이브러리 관리 · 설정 · 소재 만들기’ ③ 좌측 소재 라이브러리 트리 + 폴더 검색 + 휴지통 ④ 경로·개수·선택 수, 검색 범위(전체/이름/모델번호/상품코드) + 검색어 ⑤ 툴바 ⑥ 표 또는 카드 ⑦ 페이지(40개/페이지, 이동)
URL 상태
탭·라이브러리·페이지·보기 방식이 쿼리에 들어갑니다: tpl=libtemplate.general&lib=1&qlibs=1,39,3,112&p=1&mode=1(mode 0=카드, 1=표), 폴더는 ofi=<폴더 obsId>, 휴지통은 libtype=dustbin.
HP3
같은 배치로 구현. 페이지 크기는 HP3 공통 Pagination(20/50/100)을 씁니다. 표/카드 보기와 컬럼 구성은 보는 사람 브라우저에 기억합니다.

2-2 폴더 트리 bgs/businesscat

무엇을 하나
소재 라이브러리마다 폴더(업무 분류, businesscat)를 계층으로 관리합니다. 폴더를 누르면 그 폴더 상품만 보입니다. 쿠지알러는 해당 폴더 직속 상품만 보여 줍니다(예: ‘가구(0)’).
폴더 메뉴 (⋯)
하위 폴더 만들기 · 이름 변경 · 삭제 · 표지 설정 · 폴더 숨기기. 숨긴 폴더는 설계 툴에 보이지 않고 회색 아이콘으로 표시됩니다.
데이터
노드: obsId, name, order, cover, hide, children, catIdsWithChildren, syncData. 상품 조회는 brandgood/enterprise?catid=<obsId>.
HP3
⋯ 메뉴 5개 모두 구현. 소재 라이브러리 노드의 ⋯에서 최상위 폴더를 만듭니다. ‘하위 폴더 상품 포함’ 체크(기본 켬)를 추가해 상위 폴더에서도 전체를 볼 수 있게 했습니다(쿠지알러 방식은 체크 해제와 같음).

미구현 · 후속 과제

  • 백엔드 저장 — 지금은 브라우저 저장(localStorage). 운영 전 API·DB(상품·폴더·이력 테이블)로 옮겨야 다른 운영자와 공유됩니다.
  • 파라메트릭 모델 에디터 연결 (반영됨) — ‘소재 만들기’의 파라메트릭 모델 카드만 에디터를 엽니다(모델 유형 선택부터). 다른 카드는 쿠지알러처럼 각자의 업로드 화면으로 갑니다. 목록·상세의 ‘모델 편집’으로 다시 열고, ‘저장 후 입고’로 갱신합니다.
  • 남은 모델 데이터 작업 — 3D 모델 분할(분할면·저장), 3D 재질 교체·범례 태그·분할 전처리·설비 분류, 에디터의 빠른 모델링·변수 계열·외부 값·플러그인은 쿠지알러 동작을 확인한 뒤 진행.
  • 화면 미확인 카드 — 3-2 절 목록. 쿠지알러 화면 확인(보기만) 후 이식.
  • 업로드 변환 — .fbx·.glb 는 브라우저에서 변환(src/data/fbxConvert.ts). .skp·.max·.3dm·압축 파일은 변환 서버가 있어야 합니다.
  • 기존 ‘상품 관리’와 통합 — HP3 기존 상품(Products.tsx)과 이 라이브러리 상품의 관계(같은 원장으로 합칠지)를 결정해야 합니다.
  • 쿠지알러 동기화 — 시드는 분석 시점 스냅숏입니다. 주기 동기화는 위 API 참고 상자 내용대로 방식 결정 필요.
  • 이미지 — 상품 이미지는 쿠지알러 CDN 주소를 그대로 씁니다. 사내 CDN으로 옮길지 결정 필요.
